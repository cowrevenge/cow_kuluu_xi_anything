# 0x102d7c47 - reading (handed out by loopy; 258 bytes, 107 sites, 1 callee)

Rotation-matrix builder: `fsincos` of the caller's angle, the caller's axis copied into the frame with
three DF-sensitive `movsd`, a table routine called on the copy, and a 4x4 matrix written at [ebp+8].
Fully disassembled (tools/cow/disasm.py 0x102d7c47 0x102d7d49). The x87 register stack is half-traced;
the trace done so far is below and should NOT be redone.

## Shape
- `push ebp / mov ebp,esp / sub esp,0x1c / push esi / push edi`, epilogue `pop edi / pop esi / leave /
  ret 0xc` -> stdcall, THREE args: [ebp+8] matrix out (eax from 0x102d7c88), [ebp+0xc] axis vector
  (esi, read by three movsd), [ebp+0x10] angle.
- **[ebp+0x10] is overwritten and reused as scratch** - `fstp [ebp+0x10]` at 0x102d7c79 and again at
  0x102d7c96, and it is read back at 0x102d7c8b/0x102d7cbc/0x102d7cdb. So it is not "the angle" after
  0x102d7c79; it holds, in order, (1-cos) and then kx*ky*(1-cos). Same for [ebp+0xc]: `fst [ebp+0xc]`
  at 0x102d7cca puts ky*sin into the axis-pointer slot and 0x102d7d05 reads it back. A conversion that
  keeps them in host locals loses those two stores and reads the wrong value at the sites marked.
- Two frame pointers are set up and used indirectly: `lea eax,[ebp-4] / mov [ebp-0xc],eax` and
  `lea eax,[ebp-8] / mov [ebp-0x10],eax`, then `mov eax,[ebp-0x10]` / `mov edx,[ebp-0xc]` at
  0x102d7c5b/0x102d7c5e and the two `fstp`s go through [edx] and [eax]. Both are stores into the frame
  and both are in the trace.
- [ebp-0x1c,-0x18,-0x14] = the axis (x,y,z when DF=0), copied by three `a5`/movsd at 0x102d7c75,
  0x102d7c7c, 0x102d7c82 - INTERLEAVED with `fstp [ebp+0x10]`, two `lea eax,[ebp-0x1c]` and two
  `push eax`, so the store order is: [ebp-0x1c], [ebp+0x10], [ebp-0x18], [ebp-0x14]. DF is fuzzed by
  cowdiff, so the three sources are [esi], [esi+4], [esi+8] with DF clear and [esi], [esi-4],
  [esi-8] with DF set; model it on g->df as f_102d9502 does.

## The callee, and what is already available
- 0x102d7c83 `call 0x102d64b1` = `jmp dword ptr [0x103cc42c]` - the vector3 table thunk. **The bridge
  already exists**: `cow_call_vector3_from_table(CowAddr retaddr)` (layout/calls.c) with
  COW_ADDR_VECTOR3_TABLE_THUNK / _SLOT in layout/addresses.h. It is used by the hand unit f_102d9502
  with RETURN_B; this site needs a THIRD return-address macro, COW_ADDR_VECTOR3_TABLE_RETURN_C =
  0x102D7C88u, because the call's return address is a word written into the guest stack.
- Two args are pushed, both `lea eax,[ebp-0x1c]` - the same address twice (0x102d7c7d and 0x102d7c81),
  so in=and out= are the same buffer. Pushes land at esp-4 and esp-8 below the frame; nothing adds esp
  back afterwards, so the callee cleans them and the SEED MUST STUB the thunk with pop 0x8 (the slot's
  file image is the unconverted refresh trampoline, which recurses under fuzzing - see cluster 7).
- fsincos semantics, confirmed against side A rather than guessed: `{ double x = x87_s0; x87_s0 =
  fr_cw(cw, sin(x)); X87_PUSH(fr_cw(cw, cos(x))); g->c2 = 0; }` - so after it st0 = cos, st1 = sin, and
  the `fstp [edx]` at 0x102d7c66 stores COS to [ebp-4] while `fstp [eax]` at 0x102d7c68 stores SIN to
  [ebp-8]. [ebp-4] = cos, [ebp-8] = sin. fcw is pinned 0x027F so fr_cw is the identity, and the CRT
  sin/cos are what side A calls (precedent: src/geom/cow_102d8be9).

## x87 trace: DO NOT TRUST THE ONE BELOW - use the generated body instead
A second pass found an error in this hand trace: after the `fstp [eax+8]` at 0x102d7cd1 the stack still
holds `ky*sin` (pushed at 0x102d7c4 and never popped until the `fstp st(0)` at 0x102d7cd4), and the trace
below discards it. Every depth after 0x102d7cd1 is therefore wrong by one, which also invalidates the
"m02 is not Rodrigues" observation - that was probably my slip, not the entry's arithmetic.

**Method for the next pass: do not simulate the register stack by hand at all.** The generated body in
generated/all/funcs_049.c is already a faithful per-instruction transcription that names the physical
register every op touches (`x87_s0`, `x87_s1`, ... with X87_PUSH/X87_POP spelled out), so read the
operands off that C instead of re-deriving them from the disassembly. It is the same source side A is
compared against, so it cannot drift the way a hand trace can. Cross-check the field count and the
store offsets against the disassembly, but take the arithmetic from the C.

What survives from the trace below, because it does not depend on the lost element: the [ebp-4]=cos /
[ebp-8]=sin assignment, the two host-slot scratch traps at [ebp+0x10] and [ebp+0xc], and m00 =
kx^2(1-cos)+cos.
