# The loop

I am the conversion loop. Read this at the start of every unit and again after any compaction or
restart, then continue from `cow/wip/`. State lives in the repo — ledger, names.csv, git log,
`loop.log`, `cow/wip/` — never only in chat.

## First call, every time

`python tools/cow/loopy/loopy.py next` (or the `loopy_next` MCP tool). It reads the ledger, resumes any `in_progress` unit from
`cow/wip/<hex>/`, and hands back the job: the hex, where the generated body is and how many instruction
sites it has, the callee count, attempts left, and the style rules. After a compaction that call IS the
resume step - do not re-plan from memory and do not pick a unit yourself. Then convert, and finish with
`loopy_submit`, which runs the gate and does the ledger, wraps, status docs, the single commit and the
push in code, returning the next unit in the same result. A summary cannot end the loop, because "this
unit is done" is a tool call whose result is the next job.

**A unit is a CLUSTER, not an address** (2026-11-05 speed rework). Reading costs a pass over a body, its
callees and its oracles; the next entry that touches the same struct costs almost the same pass with the
context already in hand, and splitting one object across commits is what produced the follow-up
"machinery" commits. So a unit is **one object/struct and the functions that touch it, or a caller plus
its small callees** - the net clock, for instance, is `0x100dbeb0 / 0x100dc1f0 / 0x100dc210 /
0x100dc250 / 0x100dc260`, because they all go through `0x10492e10`. Grow it with:

```
python tools/cow/cluster.py 0x100dbeb0          # who is in this cluster, and why each one
python tools/cow/cluster.py --next              # grow around the next unit of work
```

It grows along two relations read out of the generated bytes, never guessed: **callees** (small
`f_<hex>(g)` calls in the seed's body) and **siblings** (entries reading the same non-code image address -
the object). Already-converted members stay in the cluster as context and do not count against the cap;
the cap (default 6) counts convertible work. Past 6 it is a subsystem, and a subsystem read is not one
unit. **One read, one commit, for the whole cluster.**


## Ground rules (every one of them has already bitten once)

- **PowerShell 7 only**, unwrapped, chained with `;`. Never `powershell -Command` / `pwsh -Command`.
- Each shell call is a **new process**: background jobs die with it. Anything long goes to
  `Start-Process -WindowStyle Hidden` with output to a log, then poll the log.
- Parse **only** output in a format you asked for (`--json`, `-format json`); otherwise read it raw first.
- PowerShell is case-insensitive with short aliases (`h r gc ls cd sc`): never name a function,
  variable or alias with a short name; always `$`.
- Call only tools in the tool list, by their exact names. Read the error and retry correctly; never
  end a turn on a failed call.
- Settle every question by **reading code** — the generated C first, then the oracles. Never launch
  the game, the launcher, Docker or LSB. No registry writes, nothing under `C:\PhoenixXI`.
- **Never run `goose doctor`** (it starts an agent session; it is not a read-only check).
- No throwaway `python -c`: a probe worth running twice is a file in `tools/cow/` with argparse.
- Never commit game data: no DLL/DAT/ROM bytes, no copied tables, nothing from `generated/` or `build/`.
- Upstream `recomp/`, `meta/`, `tests/` are read-only. The three `# COW:` lines in `tools/build.py`
  are the only upstream edit. Our code: `cow/ layout/ src/ runtime/cow/ tools/cow/ docs/cow/` and the
  marked block in `README.md`.
- Git: commit, fetch, plain fast-forward push to `origin main`. No reset, stash, rebase, force-push,
  branch switch or new branch. **If a push is rejected, stop and report.**
- **One script, once per commit: `python tools/cow/commit.py`.** It regenerates the ledger-derived
  artifacts (wraps, the README block, `STATUS.md`, `NAMES_TODO.md`), stages the whole area the unit may
  change, and commits + pushes. **Never hand-edit the bookkeeping and never `git add` by hand**: a
  README/STATUS edit is overwritten at the next regeneration, and a hand-picked `git add` is exactly how
  a unit landed its `.c` without the `layout/` header it needed, leaving HEAD unbuildable and forcing a
  second "machinery" commit. That failure mode is now closed in code: `commit.py` stages `src/`,
  `layout/`, `cow/`, `ledger/`, `runtime/cow/`, `docs/cow/`, `README.md` and `loop.log` as one commit,
  and REFUSES to commit if anything outside that area is dirty.

## Oracle order

1. **the generated C** (`generated/all/funcs_*.c`) — the truth about this build, byte for byte;
2. `vendor/kuluu/.agents/skills/retail-observe/references/*.md`;
3. `vendor/cow_ffxi_disassembly` — pass docs for meaning, and `Disassembly_Tools/artifacts/
   ffximain_tables_v0.zip` (class names, vtables, strings, seeds, leaked source paths) for names;
4. `vendor/xi-on-anything` (the pristine fork) for how the runtime and hosts are meant to work;
5. `vendor/xi-tools` and `vendor/POLUtils` for DAT/ROM formats.

The vault's tables describe **its** build, not ours: only 60.44% of our function bytes match it
(`python tools/cow/image_cmp.py --mode functions`). A claim from an oracle is usable once
`image_cmp.py`/`oracle_probe.py` or the generated C confirms it; class-name and string addresses are
stable, so those transfer; a vtable slot only after `--mode vas` says the bytes match.

## Per cluster, forever

1. **Precheck.** Tree clean apart from this cluster's own WIP; `HEAD == origin/main`; build green at
   HEAD (`pwsh -NoProfile -File tools/cow/build_check.ps1`). If the model or the build is down, wait and
   retry - do not quit.
2. **Resume first.** Any ledger row with `status=in_progress` continues from `cow/wip/<hex>/`.
3. **Grow the cluster.** `python tools/cow/cluster.py --next` - the seed plus its small callees plus the
   entries that touch the same object. Mark the members `in_progress` with a one-line note and
   `python tools/cow/phase.py mark start --cluster <seeds>`.
4. **Read once.** The whole cluster's generated bodies, its callees, its oracles, and what `layout/`
   already knows about the object. `phase.py mark read_done`. This is the step the cluster exists to
   save: do not start writing entry 2's code from a reading you did for entry 1 yesterday.
5. **Write the cluster.** One file per entry (a shape is a table row, never a file): the user function
   plus its `COW_ADAPTER`, and the `layout/` and `cow/names.csv` entries the reading produced. Headers
   are a short purpose + an evidence list - see `STYLE.md`; `gate.ps1` now fails a disassembly listing.
   `phase.py mark write_done`.
6. **Prove it.** `cowdiff.py <hex>` per entry; the table's rows are proven in one batch by
   `table_proof.py`. `phase.py mark cowdiff_done`.
7. **Mutate it - only when that is the rule** (see *Mutation policy* below): a code shape or a harness
   feature we have not met before, or one cluster in twenty.
8. **Gate** each entry: `pwsh -NoProfile -File tools/cow/gate.ps1 <hex>` (add `-SkipBuild` while
   iterating; the final run is full). `phase.py mark gate_done`.
   - **PASS** -> `loopy submit` / `setstatus.py ... --status done`, then **one**
     `python tools/cow/commit.py --cluster <entries> --subject 'cow: ...'`. One cluster, one commit.
   - **FAIL** -> **CHECKPOINT**, fix, re-run; at most **3 attempts**. Still failing -> copy the attempt
     to `attempts/<hex>/` (gitignored), restore **only the paths you touched** from HEAD, book the
     failures with the gate's reason, and commit. The gate decides; my opinion does not.
9. **Append one line per entry to `loop.log`** (`UTC entry name confidence result minutes`) and delete
   `cow/wip/<hex>/` in the same commit. Next cluster. Do not stop for names, failures or long runs.
10. **Every 50 finished units**: review that batch against the oracles - names, types, layout only; the
   gate must still pass; **REVIEW** commit (`python tools/cow/review_pass.py --recent 50 --apply`).

## Mutation policy (when the proof gets a proof)

`tools/cow/mutate.py` breaks the source on purpose and checks that cowdiff notices. It is the most
expensive thing the loop does per unit, and its value is not per-unit - it is in telling us the
*checker* works, which is information that carries to every later unit of the same shape. So:

- **always** mutate when the cluster contains a **code shape we have not met before** (a new x87
  pattern, a new calling convention, a new kind of loop or switch), because that shape is what every
  later unit of it will be trusted to have gotten right;
- **always** mutate when a **harness feature is new or changed** (a cowdiff comparison, a pin, a stub,
  a seed key) - that is how REFERENCE.md P4 was found, and how it was proven closed;
- **otherwise sample**: one cluster in twenty (`entry`'s low nibble, or a counter in `loop.log`).
  Record the sampled choice in the commit message so the sampling is auditable, not remembered.

An equivalent mutant is not a hole and must be written down as what it is (see
`cow/mutations/100dc210.json` M8), because "the checker missed it" and "the mutation could not be
observed" look identical in a log and mean opposite things.

## Tools are built BETWEEN clusters

Never mid-unit. A tool change in the middle of a cluster means the unit's commit contains harness
changes nobody gated against, and the next unit inherits a checker that moved under it. When a need
for a tool appears while converting: write it in `cow/wip/NOTES.md`, finish the cluster, commit it,
and build the tool as its own `--machinery` commit before the next cluster starts. `commit.py` enforces
the split - `tools/cow/` is only stageable with `--machinery`.

## Commit points

| when | message |
|---|---|
| FINISH - a cluster passes the gate | `cow: <hex>[ +<n> more] <name> [<confidence>]` - **one commit per cluster**, made by `tools/cow/commit.py` |
| FAIL — a unit is given up | `cow: <hex> failed: <reason>` |
| CHECKPOINT — any gate run that does not pass, and at least every 15 min inside a unit | copy WIP to `cow/wip/<hex>/` (tracked, never compiled), `status=in_progress` with a one-line note, `cow: checkpoint <hex>: <note>` |
| RESUME — after compaction/restart | re-read this file, the ledger and `cow/wip/`, then `cow: resume <hex>` |
| REVIEW — after each review pass | `cow: review <first>..<last>` |

## Tools

```
python tools/cow/cluster.py --next             # the unit: seed + small callees + same-object siblings
python tools/cow/phase.py mark <phase> --cluster <seeds>   # read/write/cowdiff/gate/bookkeeping timing
python tools/cow/phase.py report               # where the last clusters' minutes actually went
python tools/cow/ledger.py                     # rebuild the ledger from meta + generated/all
python tools/cow/setstatus.py --summary         # where the loop stands, what is in progress
python tools/cow/cowdiff.py 0x… --json          # the behaviour proof (also --count, --write-unreached)
pwsh -NoProfile -File tools/cow/gate.ps1 0x…    # the judge (19 checks; 11 for a tabled row)
python tools/cow/genwraps.py [--check]          # publish the wraps the ledger says are done
python tools/cow/status.py --describe '<msg>'   # README block, STATUS.md, NAMES_TODO.md (commit.py does it)
python tools/cow/mktable.py --write / --check   # the trivial table: <=8-byte shapes, one row each
python tools/cow/table_proof.py [--check]       # prove every row by cowdiff in one batch
python tools/cow/commit.py --cluster … --subject …  # THE commit: regenerate, stage, commit, push
python tools/cow/rename.py <old> <new> [--confirm]
pwsh -NoProfile -File tools/cow/build_check.ps1 # host + difftest + boot64 (BUILD_CHECK PASS/FAIL)
python tools/cow/oracle_probe.py / image_cmp.py # what the oracles still mean for our build
```

## Halt only on

a `STOP` file in the repo root (finish the current unit first) · a rejected push · a red build at HEAD
that I cannot fix within my own last commit · an unexpectedly dirty tree · 10 consecutive failures.
On a halt: write `docs/cow/LOOP_HALT.md` with the reason, run `status.py` (the README shows
**HALTED** and why), commit, push, stop.

## Proof before booking (the no-stub rule)

The unit is not ours to book until we can say **who calls it**. `tools/cow/chain.ps1 -Units N` runs the
whole recipe per unit:

```
python tools/cow/mktable.py --write                        # FIRST: is it a shape? then it is a ROW, no file
python tools/cow/mkret.py <hex> --write --prove --json     # a real function: reads the original AND asks
python tools/cow/loopy/loopy.py submit <hex> --name <from the proof> --confidence <c> --file <f> --oracle <citation>
```

**A <=8-byte entry is a row, never a file.** `mkret.py` and `mkaccessor.py` now refuse one and print the
`mktable.py` command instead, because the shared bodies their generated files called
(`src/util/cow_return.c`, `cow_addrs.c`, `cow_accessors.c`) were deleted when the table replaced them -
what they used to write no longer compiles, and `gate.ps1` refuses the file either way. `mktable.py`
re-derives kind/value/pop from `generated/all` (`--check <hex>` re-derives one row, so a row cannot drift
from the bytes), and `table_proof.py` proves the whole table in one batched harness run.

`--prove` (which calls `tools/cow/vtable_model.py`) accepts two kinds of owner: the address is a slot in a
table of code pointers - a virtual method, named `cow_vf<N>_at_<vtable>` or `cow_<vocabulary>_vf<N>` - or
code reaches it with `call`/`jmp`/`push`, which makes it a called leaf named `cow_return_at_<hex>`. With
neither, the file is not written and the row is booked `failed` with that reason; `tools/cow/gate.ps1`
refuses the same thing from the other direction (a 1-3 site body with no owner in the ledger is a stub).

**A vtable citation is only valid inside an RTTI-bounded table.** `vtable_model.py` ends a table at its
CompleteObjectLocator and refuses runs over `MAX_SLOTS = 128`, and `gate.ps1` fails any ledger row that
cites `vtable 0x… slot N/M` with M > 128 - that was a switch jump table read as a class, which is how
943 stubs once got booked as converted functions. Names or notes that came from that old model are back
at placeholder.

`unk_*` names are not booked. The names we could not do better than are placeholders in
`docs/cow/NAMES_TODO.md`, and a review pass (`python tools/cow/review_pass.py --recent 50 --apply`) is
what promotes them when the vendor tables or a vtable's vocabulary support it.

## Every turn ends with a loopy call (the rule that keeps the loop alive)

The loop is only alive if the last thing a turn does is ask loopy for work. So, always, in this order, at
the end of every turn - including a turn that ends in a summary, an answer, or a complaint:

```
python tools/cow/loopy/loopy.py next        # hand out the next unit (resumes whatever is in_progress)
```

and if `loop_forever.ps1` is not running, start it first:

```
Start-Process pwsh -ArgumentList '-NoProfile','-File','tools/cow/loop_forever.ps1','-Hours','9','-Batch','40' `
    -WindowStyle Hidden -RedirectStandardOutput build\forever.out -RedirectStandardError build\forever.err
```

If the last call of a turn is anything else - a status report, a question, a "looping!" - the loop has
stopped, because nothing else starts it. A progress note is not progress: the commit is progress, and the
commit only happens behind `loopy submit`.
